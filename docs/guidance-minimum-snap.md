# Minimum-Snap 轨迹生成器：设计依据与验证记录

本文件记录 `core/guidance/MinimumSnapTrajectory` 的设计决策、独立验证过程，
以及验证中发现的偏差与自我纠错。合入记录见 commit `fca5e1d`（PR #1）。

## 一、为什么需要这个模块

制导层此前完全不存在：控制器能跟踪一条喂给它的轨迹，但**没有任何东西会生成那条轨迹**。
本模块填补这一空白，是「从能定点悬停到能执行任务」的第一步。

## 二、数学路线

### Hermite 形式 + 无约束二次规划

每段是 7 次多项式，由段两端的「位置、速度、加速度、加加速度」8 个端点状态唯一确定
（Hermite 形式）。于是：

- 内部航点的位置固定 → 每端点剩 v/a/j 三个自由量；
- 分段多项式在内部航点天然 C³ 连续（左右端点状态共享同一组自由量）；
- 每段代价 ∫(p⁗)²dt 是端点状态的二次型，全体拼起来是自由导数 d 的无约束二次规划
  `min dᵀHd + 2gᵀd`，解为线性方程组 `H d = −g`。

由样条最优性定理，∫(p⁗)² 的全最优解是 7 次自然样条（内部航点 C⁶），它就在上述 C³
分段七次族内，所以 Hermite 族上的最小解即全局 minimum-snap，与 Mellinger & Kumar
(2011) 的端点导数法完全等价，但实现更短、约束永不违反。

### 时间分配：全局均匀缩放（精确成立，非迭代启发）

对任意时刻组 {T_i} 的最优解 p(t)，把自变量换成 t/s 即得到 {s·T_i} 时刻组的最优解
（代价只差一个公共因子 s⁻⁷，minimizer 一一对应、且解唯一）。因此缩放时间是线性变换：
速度 ×1/s，加速度 ×1/s²，jerk ×1/s³。

先用「各段独立静止-到达」的形状因子估计出比例合理的初始时刻，解一次，再按最吃紧的
约束一个比例缩到底 —— 恰好顶住约束边界，一步完成，无需迭代。

### 三个形状常数（7 次单段静止-到达轨迹 s(τ) 的峰值因子）

单段 d 米、T 秒、两端 v/a/j 为零的解具有闭式：

```
s(τ)   = 35τ⁴ − 84τ⁵ + 70τ⁶ − 20τ⁷
s'(τ)  = 140 τ³(1−τ)³                    峰值 35/16    = 2.1875 （τ=1/2）
s''(τ) = 420 τ²(1−τ)²(1−2τ)              峰值 84√5/25 ≈ 7.513  （τ=(5−√5)/10）
s'''(τ)= 840 τ(1−τ)(5τ²−5τ+1)            峰值 52.5               （τ=1/2）
```

即 `v_peak = 2.1875·d/T`，`a_peak = 7.513·d/T²`，`j_peak = 52.5·d/T³`。

时间最优性量级对照：同一约束下最优 bang-bang 需 `2√(d/a)` 秒，而 min-snap 形状给出
`√(7.513·d/a) ≈ 2.74·√(d/a)` —— 恒落后于解析下界 1.37 倍，远好于验收所要求的 2 倍。

## 三、维护者的独立验证

不复用被验者的任何测试逻辑，只用其公开接口，从四个不同角度检验。

### 1. 数学复核（sympy，独立于实现）

- 三个形状常数全部精确：`max|s'| = 35/16`、`max|s''| = 84√5/25`、`max|s'''| = 52.5`，
  端点 p/v/a/j 条件亦全部满足。
- 右端约束矩阵 `det(G) = 12·T¹⁶` 恒正 → 系统永不奇异。
- 代价矩阵 `Q[i][j] = πᵢπⱼT^(i+j−7)/(i+j−7)` 逐项吻合（π = {24, 120, 360, 840}）。

### 2. 数值验证（1e6 点密集采样）

| 检验项 | 结果 |
|---|---|
| 与解析闭式解对照 | 偏差 7.8e-15 |
| 时间尺度不变性（归一化形状） | 偏差 7.9e-14 |
| 有限差分交叉验证 vel/acc/jerk | 中位数 5.8e-8 |
| C³ 连续性（acc 最大跳变） | 3.1e-8 |
| 峰值因子与三个形状常数 | 吻合至打印精度 |

### 3. 39/39 独立复现

被验者自报 39/39，在 macOS/arm64 环境独立构建运行后复现一致。

## 四、验证中的三次自我纠错

独立验证第一版报出 `acc` 误差 3.5e5、`jerk` 误差 6.9e5，一度疑为实现缺陷。
查证后确认**全部是测试自身的错误**：

1. **二阶差分分母写错** —— 采样点在 `t±2h`，分母应为 `(2h)² = 4h²`，误写为 `h²`。
2. **中心差分跨越段边界** —— 分段轨迹在边界处读到两个不同段的系数，必然产生假误差。
3. **预测式适用条件搞错** —— 峰值预测式 `7.513·d/T²` 只在「加速度是紧约束」时成立，
   却拿去验一个实际由 jerk 约束的场景。

修正后 acc 误差降至 5.8e-8（中位数），jerk 降至 1.9e-6，acc 最大跳变 3.1e-8 —— C³ 连续性成立。

**这是本项目「以为在测 A，实际在测 B」类错误的第五至第七次实例。**
断言缺陷前必须先验证激励到达待测机制。

## 五、一处待跟进的偏差（不阻塞使用）

| 项目 | 实测 | 说明 |
|---|---|---|
| 时长 vs 闭式解 | 长 1.8e-6（相对 1e-6） | 保守方向：时间略长 |
| 峰值加速度 vs 限值 | 差 2e-6（相对 2e-6） | 保守方向：峰值略低 |

方向是保守的（安全），物理上完全可忽略。但被验者注释称峰值估计「误差降到 1e-9 量级」，
实测约 1e-6 —— **注释的精度描述偏乐观**，后续可校正。

## 七、接口契约要点

采样接口 `sample(t, FlatReference&)` 直接输出已有的 `FlatReference` 类型，控制器
一行都不用改 —— `FlatReference` 恰好需要 `pos/vel/acc/jerk` 四阶，而七次多项式天生
提供到 jerk。**少一层转换就少一处符号约定出错的机会。**

坐标系与单位约定（跨人协作最易出错处）：

- **NED**（北-东-地），z 轴朝下，高度上升 = z 减小
- 弧度制（非度）
- 四元数 Hamilton `(w,x,y,z)`，机体系 → NED

## 八、能力边界（调用方必须显式传入）

`TrajectoryLimits` 的默认值是**保守初值**，不是飞行器真实能力上限。调用方必须显式
传入实测值，尤其：

| 约束 | 数值 | 来源 |
|---|---|---|
| 水平加速度上限 | **6.87 m/s²** | `g·tan(35°)`，受 `max_tilt_deg` 限制 |
| 标称 `max_accel` | 12.0 m/s² | **实际不生效**，被倾角限制覆盖 |
| 位置环带宽 | 2 rad/s | 决定轨迹的可跟踪性 |
| 姿态环带宽 | 9 rad/s | 位置环的 4.5 倍 |

**若按 `max_accel = 12` 生成轨迹，数学上完全正确、测试全过、飞起来才炸。**

`max_jerk` 的精确上限尚未测量，暂用保守值 20.0。
